## §3 关键坑（按发现顺序）

1. **DATE_TIME 双格式 + dayfirst 翻转**：P1 发电量/P2 气象是 `dd-mm-yyyy HH:MM`，P1 气象/P2 发电量是 ISO。`dayfirst=True` 混解析把 ISO 中 day≤12 的日期翻转（2020-06-01→2020-01-06），一度让缺槽统计完全失真（"3,259 槽却缺 1,059"的悖论）。修复：`io.parse_dt` 按首值探测格式整列解析，禁止 dayfirst 混解析。加了回归测试。
2. **lightgbm 装不上**：pip 走 `http_proxy` 被拒（WinError 10061），而 curl 同代理正常——疑似防火墙拦 python.exe 回环。绕过：curl 从清华源拉 wheel，`pip install --no-index` 本地装（4.7.0）。
3. **xgboost 3.x API 变更**：`early_stopping_rounds` 从 `fit()` 挪进构造器，TypeError。改为构造器传参。
4. **LSTM 塌缩**：未标准化特征（功率单位 W，量级 10⁴）→ 3 种子全塌到常数预测（RMSE≈10.5 kW ≈ 目标标准差）。修复：train 集统计标准化特征与目标，RMSE 回到 2.3–2.9 kW 量级。
5. **pandas 3.x Index 不可变**：`dt.hour` 返回 Index，布尔赋值 `irr[mask]=0` 抛 `TypeError: Index does not support mutable operations`。测试 fixture 改 `np.asarray`。
6. **白天停机统计粒度**：按原始槽计数时 Plant_2 全员 22/22 告警（10–277 槽）——事件是真的（正午辐照 0.8–1.0 时整块 AC=DC=0），但需 (a) 连续槽合并为事件 (b) 剔除同刻全队 ≥50% 记 0 的槽（站级事件）(c) 三级严重度分级（正常/告警/重点）替代二值 flag。
7. **诊断口径不能只看效率**：两站转换效率都全队均匀（P2≈0.979；P1≈0.098 是 DC 量纲问题），效率散点看不出故障；有效信号在完整率/停机/相对出力。P1 的 ×10.2 量纲异常本身作为数据质量发现单独报告。

## §4 实验设计要点

- 预测任务：y(t+1h)，特征只用 t 及以前；`nowcast`/`weather` 双口径；按 target_dt 切天 70/15/15 防泄漏。
- 基线含槽均值（日内周期强基线），避免高估模型增量。
- LSTM 3 种子集成，历史 val RMSE 换算回 W 画曲线。
- 诊断 5 维度（完整率/停机/效率/静态损耗/相对出力）+ MAD 稳健 z + 分级。

## §6 v1.1 深化（2026-11-08）

三组实验（scripts/06–08，沿用 N1/N2 v1.1 的"补短板"节奏）：

1. **多提前量退化（06_multi_horizon）**：15min/30min/1h/2h/4h。LightGBM 缓降（P1 8.4→11.3%），持久性快速失效（8.6→36.1%，4h 时 R² 翻负）；15min 处两者几乎打平——超短提前量可直接用持久性。nowcast/weather 在长提前量基本打平（当刻天气信息随提前量衰减）。
2. **跨站迁移（07_cross_plant）**：ZeroShot 原值几乎不赢持久性（两站容量 27.1 vs 19.5 kW 量纲错位）；**容量归一化后 12.1%/11.6%**；7 天少样本 P1→P2 追平域内（11.83 vs 11.87%），P2→P1 还差 1.3pp（域内更难：P1 含 DC 量纲异常、容量更大）。与 N2 跨子集缺口 +8~21 相比，同区域光伏电站迁移性好得多。
3. **分位数概率预测（08_quantile_forecast）**：LightGBM q10/q50/q90 + 验证集共形（CQR）。原始区间天然保守（覆盖 88.5%/88.7% vs 名义 80%），校准 q̂=0 无需调整；白天覆盖≈名义（0.80），夜间过宽（0.96）；**强光桶覆盖塌到 0.455（P1）/0.727（P2）**——误差最大的时段区间反而最不可信，概率产品部署需明示。

v1.1 过程坑：

8. **SlotMean 基线泄漏**：v1.0 的槽均值用了全量数据（含测试期）统计均值（10.52%/12.14%）——偏乐观。v1.1 改为仅训练期统计（10.95%/12.96%），模型增量从 0.5pp 修正为约 1.0pp。泄漏型基线比泄漏型模型更隐蔽，写基线时要过一遍"这个统计量用了哪些天"。
9. **分位数脚本变量遮蔽**：dict 推导里 `for name, q in QUANTILES.items()` 里 `p` 被外层循环变量遮蔽 NameError——推导式内的循环变量与外层同名时留意。

产物：`results/multi_horizon_metrics.json`、`cross_plant_metrics.json`、`quantile_metrics.json` + 4 张新图；37 项单测全绿；`run_all.sh` 扩到 00–08。

### 8.2 三个新结论

1. 全局 CQR 对条件覆盖是空操作（q̂=0）；Mondrian-辐照桶把桶间极差砍半（0.47→0.20 / 0.26→0.14），宽度仅 +3~8%；小样本桶会过冲（强光桶 0.455→1.000，n=22）。
2. 云跳变事件：5–11% 样本占 23–40% MSE，事件 RMSE 2.3×、区间覆盖 0.69–0.74；下坡高估 +3~4kW / 上坡低估 −2~3.5kW（滞后机制）。
3. 智慧持久性 P1 11.74% 是强物理基线、P2 16.47% 失效；残差混合不超纯 ML（负结果）；误差 61–64% 在多变天 k_t 0.4–0.8。

### 9.2 新结论

1. **分组共形要"向全局软收缩"，v1.2 建议的"向邻桶借强度"被证伪**：shrink(k=20) 把 P1 强光桶覆盖 1.000→0.773、桶间极差 0.202→0.151、宽度 −2.7%，q̂ bootstrap std −48%/−44%；pool(bw=1.0) 反把覆盖打到 0.545、极差 0.378（辐照桶分数非同分布，池化灌进大量 0 分数）；min_n 硬阈值从过冲翻成欠覆盖 0.455 且阈值附近跳变。k∈[5,20/40] 全平台优于 raw，bw 从 0.5→1.0 结果悬崖式恶化（工程窗口过窄）。
2. **全局共形被夜间点质量钉死**：校准集 45% 样本 |r|=1 / CQR=0（夜间 AC=0 恰在 q10 下边界）→ q̂=0、λ=1.000 全为空操作；pinball 第一段只会选更宽的 [q05,q95]，二段缩放放大区间 21–34% 却没改善 P1 ramp 覆盖（0.692 不变）。白天专用校准 λ=1.063/1.153 才解锁——这是 v1.2 Mondrian 有效的机制原因，也是"校准前先查分数分布"的通用教训（与 N2 v1.3 cap 截断 0 点质量同款）。
3. **校准集自身的分布漂移是另一半原因**：强光桶 q̂_val/q̂_test = 3900/2779 W（P1，差 1121）、776/1401 W（P2，差 625），[0.5,0.8) 桶差 426–483 W。只用校准集的平滑消不掉，需更长校准窗或漂移监测。
4. **Transformer 等预算对比**：固定建模前 RNG 后 LSTM 复现 v1.0 的 10.64%/12.50%；tr_small（19.9k，参数比 LSTM 少 5%）4/4 配置优于 LSTM（−0.05/−0.88/−0.95/−0.84pp），长提前量优势更大；但 P1 仍输 LightGBM 0.37–0.62pp、仅 P2 反超 0.32–0.48pp；tr_deep（68.2k）3/4 更差（容量不是瓶颈）；**16 步窗口打乱后 3/4 配置几乎无损（+0.00~+0.04pp），只有 P1 1h +0.78pp** —— 增益主要来自特征混合而非时序依赖（特征已含 lag1/4/8/96 与 hour_sin/cos）。训练成本 2×，小样本默认仍用 GBDT。

### 9.3 踩的坑

20. **加权分位数插值口径错**：初版用"权重区间中点"插值，等权时不等价 `np.quantile(method="linear")` → pool 在 bandwidth→0 退化不到 raw（差 0.0026）。改为 type-7 坐标 `pos = level·(Σw−1)+1` 在累积权重区间内插值，并把权重整体缩放到 Σw = n_eff（Kish），使 level 修正与坐标同量纲；单测 `test_weighted_quantile_matches_numpy_when_uniform` + `test_pooled_quantiles_degenerate_to_raw_when_bandwidth_tiny` 双重钉死。
21. **归一化残差定义写错**：`r=(y−c)/h_side` 不是"溢出量/半宽"，|r|>1 才出界；单测初版把 y=3、hi=1、c=0 的 r 误写成 2.0（实为 3.0）。
22. **pinball 锐度 ≠ 区间效率**：pinball 选的是分位数头标定最好的一对，对已保守的模型会偏爱更宽的对（[q05,q95]），导致"二段缩放"净效果只是放大区间。
23. **模型初始化 RNG 未固定**：不同结构在同一 seed 下初始权重依赖全局 RNG 遗留状态，"唯一变量是结构"不成立；改为建模前 `torch.manual_seed(seed)` + `np.random.seed(seed)`，同时与 v1.0 `train_lstm`（seed 后建模）对齐。
24. **`| tail` 管道缓冲看不到后台进度**：首轮 E31 用 `python ... | tail -60` 跑了 11 分钟无任何输出，只能靠 `Get-Process python` 的累计 CPU（1977 s / 4 核）判断没卡死；改为 `python -u ... > log 2>&1` 直接 tail 日志。
25. **`pd.cut(ndarray)` 返回 ndarray**（v1.2 旧坑复现）：分组标签统一 `np.asarray(...).astype(str)`；combo 标签用 `np.char.add` 拼接避免 pandas Categorical 的对齐陷阱。
26. LightGBM 4.7 的 `eval_set` deprecation warning 无害，未改动既有训练接口以保持跨版本结果一致。
